## 2025-02-17 - API Path Traversal Prevention
**Vulnerability:** API endpoints in `evolution.py` and `wisdom.py` accepted raw `run_id` and `patch_id` parameters from requests and used them directly to construct file system paths without sanitization.
**Learning:** Framework-level path sanitization (like FastAPI's `../` normalization) may not protect against path traversal when malicious payloads are embedded within composite strings in JSON request bodies (e.g., `"patch_id": "../etc:something"`). Application-level component extraction and validation (e.g., via `validate_path_component`) must be applied to the separated string segments before resolving file system paths.
**Prevention:** To prevent Check-After-Use flaws when fixing path traversal vulnerabilities in API endpoints, ensure `validate_path_component` is called at the absolute top of the function (immediately after parameter parsing) before any business logic, database queries, or file system operations. Catch the resulting `ValueError` and raise a framework-appropriate error (e.g., FastAPI's `HTTPException(status_code=400)`) containing the `error` code, `message`, and parameter `details` to fail securely.

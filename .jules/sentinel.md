## 2024-05-15 - SQL Injection Vulnerability in StatsDB Query Execution
**Vulnerability:** The API endpoint for database statistics in `swarm/api/routes/db.py` constructed SQL queries using an f-string with an unvalidated `table` variable (`f"SELECT COUNT(*) FROM {table}"`). This could potentially allow for SQL injection attacks if an attacker were able to control the `table` input parameter.
**Learning:** Even internal query helpers (like `safe_count`) that accept dynamic parameters such as table names can introduce SQL injection vulnerabilities if the input isn't strictly validated against a known allowlist. Framework-level protections or the assumption that the helper is only called with safe inputs are not sufficient for a defense-in-depth approach.
**Prevention:** Always validate dynamic identifiers (like table or column names) against a strict allowlist (e.g., `if table not in VALID_TABLES: return 0`) before using them in SQL queries constructed with f-strings or string formatting. Parameterized queries should be used for values, but identifiers require an allowlist approach.

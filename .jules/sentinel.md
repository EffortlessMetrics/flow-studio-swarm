## 2025-03-06 - Path Traversal in Path Parameters and Request Payloads
**Vulnerability:** Path traversal vulnerability across Evolution and Wisdom API routes where `run_id`, `patch_id`, and `artifact_name` from path parameters and JSON request bodies were directly concatenated into file paths without validation. Specifically, composite strings like `"patch_id": "run_id:patch_id"` in `ApplyEvolutionRequest` were split and used directly.
**Learning:** Framework-level path sanitization (like FastAPI's `../` normalization for path parameters) does not protect against path traversal when malicious payloads are embedded within composite strings in JSON request bodies (e.g., `"patch_id": "../etc:something"`). The underlying `TestClient` may also mask path traversal vulnerabilities by normalizing paths before they reach the endpoint, meaning application-level validation must be explicitly verified.
**Prevention:** Always apply application-level component extraction and validation (e.g., via `swarm.runtime.safe_paths.validate_path_component`) to all user-supplied path components (including those split from composite JSON strings) before resolving file system paths. When testing, bypass `TestClient` to properly assert application-level validation for path parameters.

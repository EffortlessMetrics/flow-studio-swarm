## 2025-03-21 - String Interpolation in SQL Queries
**Vulnerability:** The `safe_count` function in `swarm/api/routes/db.py` used string interpolation (`f"SELECT COUNT(*) FROM {table}"`) to construct SQL queries, which is a critical pattern that could lead to SQL injection if user-controllable input reaches it.
**Learning:** Even internal helper functions used with hardcoded inputs should avoid vulnerable patterns. The string formatting for SQL identifiers (table names) cannot be parameterized in many SQL drivers, making an explicit allowlist the safest approach. Note: Avoid adding allowlists to internal functions with no user-controllable paths if it adds hidden maintenance burden ("security theater"), but in this case, defining a clear allowlist prevents future regressions when the API endpoints evolve.
**Prevention:** Never use string formatting (`f"..."` or `%s`) for SQL execution. Always use parameterized queries for values, and explicit allowlists or strictly validated schema constants for dynamic identifiers like table or column names.

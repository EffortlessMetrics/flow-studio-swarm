## 2024-05-24 - SQL Injection Risk from Dynamic Tables
**Vulnerability:** Found a SQL injection vulnerability in `swarm/api/routes/db.py` where a dynamic `table` parameter was being interpolated directly into a SQL query `f"SELECT COUNT(*) FROM {table}"` within the `safe_count` helper function. Even if only internal code uses this function, passing dynamic identifiers without sanitization or allowlists makes the application vulnerable to injection attacks if the `table` input ever becomes user-controllable.
**Learning:** This existed because `table` was assumed to be hardcoded, safe values passed internally from other functions within the module. However, security defense in depth dictates that we shouldn't rely on assumptions of internal safety; an exception exists for inherently dangerous patterns like direct SQL string interpolation.
**Prevention:** Implement strict allowlisting for any dynamic identifiers (like table names) in SQL queries. If an argument is meant to represent a limited set of internal entities, validate against an explicit list of allowed values.

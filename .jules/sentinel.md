
## $(date +%Y-%m-%d) - Path Traversal in Evolution API Endpoints
**Vulnerability:** The Evolution API endpoints (`/evolution/{run_id}`, `/evolution/{run_id}/{patch_id}`, `/evolution/{run_id}/validate/{patch_id}`, `/evolution/apply`, `/evolution/{run_id}/reject/{patch_id}`) accepted arbitrary string parameters for `run_id` and `patch_id` and used them directly to construct file paths via `runs_root / run_id / "wisdom"`. This allowed for directory traversal (e.g., passing `"../etc"` as a `run_id`).
**Learning:** Even when path parameters seem like IDs or opaque tokens, if they are eventually used in file system operations via `pathlib.Path` concatenation without validation, they introduce critical path traversal vulnerabilities. FastAPI's `TestClient` normalizes requests (e.g., collapses `..`), masking application-level path validation gaps during testing unless the endpoint functions are awaited directly.
**Prevention:** All user-supplied path components (e.g., `run_id`, `patch_id`, `flow_key`) must be explicitly validated using `swarm.runtime.safe_paths.validate_path_component` at the routing layer before any IO operations. Endpoints expecting compound strings (like `run_id:patch_id`) must split and validate each component. Tests for path traversal must invoke the internal async functions directly instead of relying solely on `TestClient`.

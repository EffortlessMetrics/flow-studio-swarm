## 2024-05-24 - SQL Injection Vulnerability in DB Stats Endpoint
**Vulnerability:** The `/stats` endpoint in `swarm/api/routes/db.py` contained a SQL injection vulnerability because it directly interpolated the `table` variable into the SQL string `conn.execute(f"SELECT COUNT(*) FROM {table}")` within the `safe_count` function. While the inputs to this function were currently hardcoded table names ("runs", "steps", etc.), this pattern created a latent risk if the function were ever exposed to user-controlled input in the future, as there was no validation.
**Learning:** Even internal helper functions used with hardcoded inputs should follow secure coding practices, especially when constructing dynamic SQL queries. Relying on the caller to always provide safe input is a fragile defense-in-depth strategy.
**Prevention:** Never use string formatting or f-strings to insert identifiers (like table or column names) directly into SQL queries without prior validation. Always validate such dynamic identifiers against a strict allowlist (e.g., `if table not in {"valid_table"}: ...`) before executing the query.

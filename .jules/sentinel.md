## 2025-02-23 - Path Traversal via Composite Request Parameters
**Vulnerability:** The `/evolution/apply` endpoint in FastAPI accepted a `patch_id` parameter that could contain a composite value (`run_id:patch_id`). It split these components and directly used `run_id` to build a file path without sanitization, leading to an unauthenticated path traversal vulnerability.
**Learning:** Application-level code often splits or parses single request parameters into multiple variables (e.g. composite IDs). Standard web framework protections (like FastAPI URL route sanitization) do NOT protect these dynamically split substrings. If they are later used in path construction, they introduce critical path traversal vulnerabilities.
**Prevention:** Any string parsed or split from user input (even if it's nested in a JSON payload or composite ID) MUST be explicitly run through application-level validation (e.g., `validate_path_component`) before it is interpolated into a file system path.

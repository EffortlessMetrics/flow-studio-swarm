## 2025-03-05 - Path Traversal in Evolution API Endpoints
**Vulnerability:** The evolution API endpoints (`/apply`, `/validate`, `/{run_id}/{patch_id}`, `/{run_id}/reject/{patch_id}`, `/{run_id}`) used user-supplied `run_id` and `patch_id` strings directly in file path constructions (`wisdom_dir = runs_root / run_id / "wisdom"`) and patch resolutions without prior validation.
**Learning:** Even when handling non-standard IDs like `patch_id` or composite IDs like `run_id:patch_id`, Fast API does not automatically sanitize OS-level directory traversal characters (`../`, `..\\`) from URL query string or path parameters. The application-level path validation using `validate_path_component` must be strictly enforced on all parameters that will be interpolated into file paths to prevent OS-level path traversal attacks, and we must make sure to handle all components of a split composite ID.
**Prevention:** Always wrap path components received from the user in `validate_path_component` catching `ValueError` and translating it into a 400 `HTTPException` before using them. When handling composite identifiers (e.g. `run_id:patch_id`), split them and validate each part individually.

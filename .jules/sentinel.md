## 2024-05-24 - API Routes Path Traversal via Dynamic Path Segments
**Vulnerability:** Path traversal vulnerability existed in `/api/evolution/` and `/api/wisdom/` endpoints where dynamic path parameters (`run_id`, `patch_id`, `artifact_name`) directly fed into OS file path constructions. Specifically, URL decoding and framework normalization routines didn't prevent encoded path traversals like `..%5c..%5cetc` from reaching business logic.
**Learning:** Application-level normalization doesn't implicitly prevent OS-level path traversal characters (`/`, `\`, `..`) when those parameters construct backend artifact storage paths, especially if the framework skips validation for implicitly assumed "safe" ID patterns.
**Prevention:** Always pipe dynamically ingested, user-supplied path components through a strict allowlist validation function (`_validate_path_param` wrapping `validate_path_component`) ensuring only alphanumeric or expected separators (like `-` or `_`) are allowed, explicitly rejecting `/` and `\`.

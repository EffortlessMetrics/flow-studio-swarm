## 2024-05-24 - SQL Injection in Dynamic Database Table Names
**Vulnerability:** A SQL injection vulnerability existed in `swarm/api/routes/db.py` within the `get_db_stats` endpoint. The `safe_count` function accepted a `table` string parameter which was directly interpolated into a SQL query `f"SELECT COUNT(*) FROM {table}"`.
**Learning:** Even though the function was only called internally with hardcoded table names ("runs", "steps", etc.), using f-strings for SQL query construction without validation introduces a significant risk. If the `safe_count` function were ever exposed or refactored to accept external input, it would become an immediate vector for severe SQL injection.
**Prevention:** When executing SQL queries with dynamic identifiers (like table or column names) via `conn.execute` or similar database drivers, never use f-strings or string concatenation. Since parameterized queries typically do not support table names, always validate the input against a strict allowlist (e.g., `if table not in {"runs", "steps", "tool_calls"}: return 0`) before constructing the query to ensure the identifier is completely safe and expected.
